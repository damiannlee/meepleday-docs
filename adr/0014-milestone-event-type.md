# 0014. 생애주기 마일스톤을 `EventType`으로 두되 피드에서 제외

- 상태: Accepted
- 맥락: 게임 페이지(S3)의 목적은 **한 게임의 생애주기 전체 파악** — 언제 펀딩했고, 생산은 끝났고, 배송 중인지. 그런데 기존 `EventType` 5종(FUNDING/PREORDER/SALE/OFFLINE_EVENT/RETAIL)은 전부 **판매·행사** 유형이라 "생산 완료"·"배송 시작"을 담을 자리가 없었음.

## 결정

- **`EventType.MILESTONE` 신설.** `startAt`만 갖는 **점 이벤트**(`endAt` 없음), `gameId` **필수** — `Event` 전체에서 `gameId`가 non-null인 유일한 유형.
- **Event / MILESTONE 판정 기준**: *그 날짜에 유저가 뭔가 할 수 있나(사거나·후원하거나·가거나)?* → **있으면 Event, 없으면 MILESTONE.**
- **노출은 게임 페이지 생애주기 한 곳뿐.** 홈 피드·유형 필터 칩·검색 결과에서 제외하고, 이벤트 상세 페이지와 OG 프리렌더 대상도 아님(단독 공유 가치가 없어 유입 채널이 아님). 파급 지점 전량은 [spec/tracking-model.md](../spec/tracking-model.md)에 매트릭스로 고정.
- **북마크 불가** — 마감이 없어 챙길 것이 없음. 마일스톤 정보는 **관심 게임 팔로워 알림으로만 도달**([ADR-0013](0013-bookmark-vs-game-follow.md))하며, 이것이 두 추적 개념이 별개여야 하는 가장 선명한 근거.
- **종류는 `생산 완료` / `배송 시작` 2종으로 시작.** 해외·국내 시차는 기존 `region`(DOMESTIC/OVERSEAS) 재사용.
- 검수 게이트는 `Event.moderationStatus` 그대로 재사용([ADR-0002](0002-moderation-on-event.md)) — 새 검수 개념 불필요.

## 근거

- **별도 엔티티가 아닌 이유**: 생애주기 뷰가 "펀딩(기간 바) + 배송 시작(점)"을 **한 시간축**에 그려야 함. 테이블이 둘이면 정렬·페이징·컴포넌트가 전부 이중화됨. "피드에서 빠지는 유형이 하나 있다"는 예외 한 개가 병합 로직보다 저렴.
- **정보원이 로그인 벽 뒤에 있음**: 생산·배송 소식은 킥스타터·게임파운드의 **백커 업데이트**에만 존재 → 후원하지 않은 운영자는 관측 자체가 불가능. 따라서 마일스톤은 제보 개방이 전제인 유형이며, 그 제보 흐름 설계가 [spec/tracking-model.md](../spec/tracking-model.md)에 포함됨.
- **오정보 리스크가 가장 낮은 유형**: 마감이 없어 틀려도 유저가 돈이나 기회를 잃지 않음(펀딩 마감일 오류와 대비) → 제보를 열어보기에 가장 안전한 지점.

## 기각한 대안

- **`Game.productionStatus` 필드**: 단조 증가하는 **이력**을 단일 값으로 뭉개면 "언제 배송이 시작됐나"라는 시점 정보가 소멸. 배송은 지역별 시차가 있어 단일 값으로 표현 불가.
- **별도 `GameMilestone` 엔티티**: 피드 오염을 쿼리 단계에서 원천 차단하나, 게임 페이지 타임라인이 두 소스를 병합해야 함(위 근거 참조).
- **스트레치골을 마일스톤으로 등록**: 캠페인당 수십 건 → ① 수동 등록 서비스에서 운영 부담 폭발 ② 피드에 나오지 않는 행이 `Event`를 뒤덮어 `(moderation_status, end_at)` 인덱스 효율 저하 ③ 게임 페이지가 스트레치골로 도배돼 정작 중요한 "국내 정발"을 밀어냄. 남긴다면 `"스트레치골 전량 달성"` 요약 1건.
- **`펀딩 종료` 종류**: `endAt` 경과로 `ENDED`가 이미 파생되므로([ADR-0004](0004-derived-status.md)) 같은 사건이 생애주기에 두 번 찍힘.
- **`국내 발매` 종류**: 실제로 살 수 있는 일정이므로 `RETAIL`/`PREORDER` Event가 맞음 — 위 판정 기준에 정면 위배.
- **`일정 지연` 종류**: 백커 업데이트에서 가장 흔한 소식이고 "내가 후원한 게 언제 오나"([PRD §8.2](../prd.md#82-게임-단위-생애주기-추적))에 직접 답하나, 날짜가 *공지일*인지 *새 예상일*인지 애매하고 점 이벤트로는 정보가 빈약. **실제 제보가 관측되면 추가**.

## 트레이드오프 / 후속 과제

- "피드에 나오지 않는 `EventType`"이라는 예외가 피드·필터 칩·검색·상세·OG 여러 지점에 파급 → 매트릭스로 고정하지 않으면 구현 중 누락 위험.
- **`MILESTONE`은 파생 상태 산출 대상이 아님** — `endAt`이 없어 현행 규칙대로면 `ONGOING`에 영구히 머무름. [ADR-0004 개정(2026-08-02)](0004-derived-status.md#개정-2026-08-02--milestone-제외와-예고-승격-규칙) 참조.
- `openapi.yaml`의 `eventType` enum에 `MILESTONE` 추가는 **백엔드 구현 시 gradle task로 재생성** — 이 문서에서 수기 편집하지 않음(생성물 단일 소스 원칙).
