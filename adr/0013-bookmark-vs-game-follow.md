# 0013. 추적을 북마크(일정)와 관심 게임(팔로우) 두 개념으로 분리

- 상태: Accepted
- 맥락: [PRD §4.7](../prd.md#47-추적-북마크)은 "개별 이벤트 북마크" 하나만 정의했으나, 화면이 두 축으로 갈림 — 홈 일정 뷰는 **다양한 일정을 한눈에**(횡단), 게임 페이지는 **한 게임의 생애주기**(종단)가 목적. "북마크의 대상은 일정인가 게임인가"가 미해결로 남아 있었음.

## 결정

- **북마크 = `Event` 대상, 관심 게임(팔로우) = `Game` 대상. 두 개념 병존.**
- 알림 역할을 분리 — 북마크는 **마감 임박**, 팔로우는 **신규 일정 등록**.
- **팔로우는 새 일정을 자동 북마크하지 않는다.** 등록 알림 1회 + 내 목록 자동 노출까지만. 마감 임박 알림 대상은 유저가 명시적으로 북마크한 것뿐.
  ```
  팔로우 → 새 일정 등록 시 알림 + 목록 노출        (발견)
            ↓ 유저가 그 일정을 북마크
  북마크 → 마감 임박 알림 대상으로 승격            (추적)
  ```
- **내 목록 화면은 하나**("내 일정"). 팔로우로 유입된 항목에만 배지 — 유저가 탭을 고르지 않게.
- 아이콘·동사를 분리(일정 = "저장", 게임 = "관심 게임"). 둘이 한 화면에 공존하는 지점은 **이벤트 상세 한 곳뿐**이며, 북마크는 헤더의 1급 액션, 팔로우는 "연결된 게임" 카드에 종속된 보조 액션으로 계층을 나눔.

## 근거

- **pull vs push.** 등록만 되면 어떤 일정이든 북마크 가능 — 문제는 "등록됐다는 걸 유저가 알아야" 한다는 것. 발견 책임이 유저에게 남으면, 흩어진 정보를 매번 순회하는 반복 노동([PRD §2](../prd.md#2-타깃-사용자) Pain 2)을 게임 축에서만 방치하는 셈.
- **수명이 다름.** 일정 북마크는 마감과 함께 죽지만, 게임 관심은 펀딩 → 생산 → 배송 → 정발까지 수년 유지돼야 함.
- **`gameId`가 nullable**([ADR-0007](0007-game-entity.md)). 종합 오프라인 행사·여러 게임 묶음 특가는 게임에 걸 수 없음 → 게임 전용 북마크는 행사를 못 담아 정체성 재정의([PRD §1](../prd.md#1-서비스-정체성))와 충돌.
- **퍼널과 정합**([PRD §3](../prd.md#3-핵심-가치와-퍼널)) — 팔로우가 발견 단계를, 북마크가 추적 단계를 담당. 개념이 둘인 것이 오히려 퍼널 구조를 그대로 반영.

## 기각한 대안

- **게임 전용 북마크**: 멘탈모델("관심 있는 건 게임이지 일정이 아니다")에 가까워 보이나, `gameId` nullable 때문에 오프라인 행사를 추적할 수단이 사라짐. 결정적 기각 사유.
- **일정 북마크만 두고 게임 추적을 파생** (북마크한 일정의 `gameId`로 같은 게임의 새 일정을 알림): 개념 추가 0개, 혼란 0으로 가장 매력적인 대안. 기각 사유 ① 특가 하나 북마크를 "이 게임 평생 추적" 신청으로 오추론 → 알림 피로 ② 북마크는 마감과 함께 죽는데 죽은 북마크가 계속 알림을 트리거 ③ 명시적 해제 수단 부재 — 유저가 자기 구독 상태를 보지도 끄지도 못함 ④ `gameId` 없는 북마크는 파생이 일어나지 않아 "어떤 건 알려주고 어떤 건 안 알려주는" 들쭉날쭉한 동작.
- **팔로우가 새 일정을 자동 북마크**: 클릭이 1회 줄지만 유저가 원치 않은 마감 임박 알림까지 받게 됨 → 두 개념의 역할 구분이 UI에서 무너짐.
- **마이페이지에 "북마크"/"관심 게임" 탭 분리**: 구현은 단순하나 "내가 그거 어디에 저장했더라"가 발생. 단일 목록 + 배지로 대체.

## 트레이드오프 / 후속 과제

- **개념이 둘이라 온보딩 설명 부담**이 생김. UI 계층·문구·알림 문구 차이로 흡수하고 별도 튜토리얼은 만들지 않음(관측 후 재검토).
- **착수 순서**: 북마크 먼저, 팔로우는 **게임당 평균 연결 이벤트 2건 이상**이 관측된 뒤([PRD §8.2](../prd.md#82-게임-단위-생애주기-추적) 진입 조건과 동일 논리). 게임당 일정이 1건뿐이면 팔로우가 북마크의 동의어가 되어 두 개념의 존재 근거 자체가 사라짐 — 구현 사정이 아니라 기획 정합성 문제.
- 알림 발송은 [PRD §8.5](../prd.md#85-마감-임박-알림) 진입 조건에 종속. 팔로우의 신규 등록 알림도 같은 게이트를 공유하며, 알림 이전 단계에서는 목록 노출로만 동작.
- 팔로워가 0인 게임의 마일스톤([ADR-0014](0014-milestone-event-type.md))은 도달처가 없음 → 검수 큐 정렬 신호로 활용([spec/tracking-model.md](../spec/tracking-model.md)).
- 행동 규칙·엔드포인트·제보 갈래 상세는 [spec/tracking-model.md](../spec/tracking-model.md).
