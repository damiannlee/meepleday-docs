# 추적 모델 기능명세 — 북마크 · 관심 게임 · 마일스톤

> 설계 근거는 [ADR-0013](../adr/0013-bookmark-vs-game-follow.md)(추적 두 개념 분리) · [ADR-0014](../adr/0014-milestone-event-type.md)(마일스톤 유형). 이 문서는 **행동 규칙**만 다룸.
> 요청/응답 스키마의 단일 소스는 [openapi.yaml](../openapi.yaml) — 구현 시 gradle task로 재생성되며 여기에 전사하지 않음. 아래 엔드포인트는 **미구현 상태의 안(案)**.
> 북마크의 M3 위치·완료 기준은 [spec/m3-tracking.md](m3-tracking.md).

## 0. 두 개념 요약

| | 대상 | 유저 언어 | 알림 | 수명 |
|---|---|---|---|---|
| **북마크** | `Event` | "이 일정 놓치지 말자" | 마감 임박 | 그 일정이 끝나면 소멸 |
| **관심 게임(팔로우)** | `Game` | "이 게임 소식 계속 줘" | 신규 일정 등록 | 해제할 때까지 |

- 팔로우 = 발견, 북마크 = 추적 — [PRD §3](../prd.md#3-핵심-가치와-퍼널) 퍼널에 그대로 대응.
- 알림 발송 자체는 [PRD §8.5](../prd.md#85-마감-임박-알림) 진입 조건에 종속. 그 이전 단계에서는 **목록 노출로만 동작**.

---

## 1. 북마크

**엔티티** — `Bookmark(user_id, event_id, createdAt)`, `(user_id, event_id)` unique.

**엔드포인트(안)** — `POST`/`DELETE /api/events/{id}/bookmark`, `GET /api/me/bookmarks`.

**규칙**
- `MILESTONE` 유형은 **북마크 불가**(마감이 없어 챙길 것이 없음) — 요청 시 거부.
- 상태는 저장하지 않고 파생([ADR-0004](../adr/0004-derived-status.md)) — 목록 조회 시 N+1 주의(배치 로딩).
- 무산된 예고를 북마크한 경우 목록에 **"취소됨"** 으로 표기(row는 `REJECTED`로 남음).
- 타 유저 자원 접근 차단 — 조회·삭제는 소유자 검증.

## 2. 관심 게임 (팔로우)

**엔티티** — `GameFollow(user_id, game_id, createdAt)`, `(user_id, game_id)` unique.

**엔드포인트(안)** — `POST`/`DELETE /api/games/{id}/follow`, `GET /api/me/follows`.

**규칙**
- 팔로우 중인 게임에 **새 `Event`가 `PUBLISHED`되면** 알림 1회 + 내 목록에 자동 노출.
- **자동 북마크하지 않는다.** 마감 임박 알림 대상은 유저가 명시적으로 북마크한 것뿐.
  ```
  팔로우 → 새 일정 PUBLISHED → 알림 1회 + 목록 노출   (발견)
            ↓ 유저가 [저장] 클릭
  북마크 → 마감 임박 알림 대상으로 승격                (추적)
  ```
- `MILESTONE` 등록도 팔로워 알림 트리거 — 마일스톤이 유저에게 도달하는 **유일한 경로**.
- 알림 중복 방지는 `(user_id, event_id)` 단위 — 마감 임박 알림 도입 시의 `NotificationLog`와 같은 게이트를 공유([spec/m3-tracking.md §2](m3-tracking.md#2-마감-임박-이메일-알림-보존--m3-범위-아님)).

## 3. 내 목록 (S7)

- **탭을 분리하지 않는다.** 북마크 + 팔로우 유입 항목을 **단일 "내 일정" 타임라인**에 병합, 피드와 같은 기간 그룹 레이아웃 재사용([ADR-0008](../adr/0008-timeline-layout.md)).
- 팔로우로 유입된 항목에만 배지 + `[저장]` 액션 노출 → 누르면 북마크로 승격.
- 같은 일정이 양쪽 경로로 들어오면 **북마크 상태가 우선**(중복 표시 금지).
- 보조 토글: "관심 게임으로 묶기" — 게임 단위 그룹핑.

---

## 4. 마일스톤 노출 범위

`MILESTONE`은 "피드에 나오지 않는 유형"이라는 예외이므로 파급 지점을 전부 고정한다.

| 지점 | MILESTONE |
|---|---|
| 홈 피드 S1 (간트/그룹/카드그리드 전부) | **제외** |
| 유형 필터 칩 목록 | **미노출** (필터로도 호출 불가) |
| 검색 결과 ([ADR-0011](../adr/0011-search.md)) | **제외** — 게임으로 유도하는 편이 일관적 |
| 게임 페이지 S3 생애주기 | **노출 (유일한 노출처)** |
| 이벤트 상세 S2 · OG 프리렌더 | **없음** — 단독 공유 가치가 없어 유입 채널이 아님 |
| 북마크 | **불가** |
| 팔로워 알림 트리거 | **가능** |
| 파생 상태 산출 | **제외** — [ADR-0004 개정](../adr/0004-derived-status.md#개정-2026-08-02--milestone-제외와-예고-승격-규칙) |

**종류** — `생산 완료` / `배송 시작` 2종으로 시작. 해외·국내 시차는 `region` 재사용. 확장 판단 근거는 [ADR-0014 기각 대안](../adr/0014-milestone-event-type.md#기각한-대안).

## 5. 제보 갈래

마일스톤 정보원(백커 업데이트)은 **로그인 벽 뒤**라 운영자 관측이 불가능 → 제보 개방이 기능 성립의 전제([ADR-0014](../adr/0014-milestone-event-type.md)).

**진입점은 유저가 서 있는 자리마다 하나씩** — 두 입구가 한 화면에 동시에 보이는 지점이 없으므로 갈래 고민이 발생하지 않는다.

- 홈 → 기존 제보 폼(S4).
- 게임 페이지 → "이 게임 소식 알려주기" 버튼 하나. 클릭 시 첫 질문으로 분기:

| 질문: 그 날짜에 유저가 뭔가 할 수 있나? | 이동 |
|---|---|
| **예** (살 수 있거나 갈 수 있는 새 일정) | 기존 제보 폼(S4) — **`gameId` 프리필됨** |
| **아니오** (제작·배송 진행 상황) | 마일스톤 폼 |

**게임 페이지 경유의 이득** — `gameId`가 확정된 채 도착하므로 검수 부담 1위인 **게임 매칭 판정**([PRD §4.2](../prd.md#42-game-엔티티))이 해당 건에서 소멸.

**마일스톤 폼** — 자유 서술 금지. `종류 드롭다운(2종)` + `날짜` + `출처 링크(선택)`만. URL 자동 채움([ADR-0009](../adr/0009-fetch-vs-crawl.md)) 흐름을 타지 않음(공개 OG URL이 없음).

**검수**
- 게이트는 `moderationStatus` 그대로([ADR-0002](../adr/0002-moderation-on-event.md)). 폼이 좁아 검수는 "이 서술이 맞나" 판독이 아니라 **"이 날짜 맞나" 확인**으로 축소.
- 같은 `game_id` + 같은 종류 = 같은 마일스톤 → **중복 제보는 검수 큐에서 한 줄로 묶어 표시**.
- **자동 승인 임계값은 만들지 않는다** — 초기 제보자 수에서 N명이 모일 가능성이 낮고 임계값 근거 데이터가 없음. 제보량이 관측된 뒤 재검토.
- 기각 — **후원자 가중치**: 플랫폼 계정 연동이 필요한 대공사인데 얻는 것이 검수 우선순위뿐.
- 검수 큐는 **팔로워 수로 정렬** — 팔로워 0인 게임의 마일스톤은 승인해도 도달처가 없음. 부담을 줄이는 장치가 아니라 **밀려도 안전하게** 만드는 장치.

## 6. 예고 승격

`ANNOUNCED` → 확정 시 **같은 row 갱신**(새 row 금지). 무산·분기·유형 변경 처리 규칙 포함 — [ADR-0004 개정](../adr/0004-derived-status.md#개정-2026-08-02--milestone-제외와-예고-승격-규칙).

## 열린 결정 (착수 시 확정)

- 팔로우 착수 시점 — 게임당 평균 연결 이벤트 2건 이상 관측 전까지 보류([ADR-0013](../adr/0013-bookmark-vs-game-follow.md)).
- `일정 지연` 마일스톤 종류 추가 여부 — 실제 제보 관측 후.
- 마일스톤 중복 제보의 자동 승인 임계값 — 제보량 관측 후.
